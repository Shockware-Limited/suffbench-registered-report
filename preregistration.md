# Preregistration (embargoed draft) — Interfaces or bodies? A test of ε-sufficient context for LM code editing in Go

To be registered on OSF (embargoed) at the time of the MSR 2027 Registered Reports Stage 1 submission, and unembargoed on in-principle acceptance. This text mirrors the Stage 1 report; the report is authoritative.

## 1. Study information
- Title: as above.
- Authors: Jude Castiel Johansen (Shockware Limited, independent researcher).
- Description: a paired, multi-model, single-shot code-editing study that operationalises ε-sufficient context (DOI 10.5281/zenodo.23282196) as a non-inferiority test of a compiler-computed interface context against bodies and against the transitive slice, with a degradation curve at verified fixed coverage, a descriptive forward-slice contrast, and token costs.

## 2. Hypotheses (confirmatory unless marked)
- H2 (primary): A1 is non-inferior to A1b and to A2 at margin ε on Δ-pass (intersection–union).
- H1 (revised 2026-10-11): at each load level L ∈ {200k, 400k, 950k} and padding type, (a) one-sided paired superiority of A1 over A1 padded to L (degradation) and (b) TOST equivalence at ±0.05 (flatness); outcomes per level: degradation / flat / inconclusive, all reportable. Full curve at {base, 64k, 200k, 400k, 700k, 950k} reported with intervals.
- H3 (descriptive): Δ-pass-and-frame-pass, A1F vs A1, overall and by shared-helper stratum.
- H4 (descriptive): tokens, latency, cost per arm.
- H5 (added 2026-10-12, before any ablation call; confirmatory on the Phase 3 instances, exploratory on the 24 pilot instances): necessity and static predictability of dependency interfaces within A1. For each direct dependency d of W, arm A1−d is A1 with d's interface removed (dependencies grouped into at most 16 contiguous groups when there are more). Arm A1g keeps only dependencies referenced by the gold patch (oracle predictor); arm A1t keeps only dependencies referenced by the task text (inference-time predictor). Confirmatory H5a: A1g non-inferior to A1 at margin ε (paired, same bootstrap as H2). Confirmatory H5b: A1t non-inferior to A1 at margin ε. Descriptive: fraction of dependencies necessary (removal lowers the instance pass rate by more than ε at k=20), precision and recall of each predictor against empirical necessity, slack = tokens(A1)/tokens(W ∪ necessary interfaces), and the count of removals that raise the pass rate by more than ε. The reference rules (selector alias.Name resolved through W's imports, or a selector v.Name where Name is exported by exactly one direct dependency, since gold patches reach dependency types through variables; whole-word package name of length ≥4 or unique exported identifier of length ≥6 in the task text) and k=20 are fixed here; any change after the exploratory run is dated below.
- Control: A∅ (task only) per repository.

## 3. Design plan
- Within-instance (paired) design (revised 2026-10-11): dense cheap model (Haiku 5.5 class) on every arm within its window, k=10; one open-weights 1M-window model at temperature 0 on every arm, k=3 on A∅/A1/A1b/A2 and k=1 on padded and retrieval arms; frontier model (Opus 5 class) on A∅ for all instances (the screen) and on A1, A1b, A2, P200 over a stratified 100-instance subset (strata: repository × write-set size; seed 20261120), P950 over a 30-instance sub-subset. Confirmatory H2 is carried by the dense and open-weights models; the frontier replication is descriptive.
- Blinding: the analysis script is written and frozen before the confirmatory run; outcomes are computed mechanically by tests.
- Randomisation: order of arms within an instance is irrelevant (independent calls); provider and quantisation pinned.

## 4. Sampling plan
- Population: fail-to-pass commits after the latest documented cutoff of the evaluated models, in 5–8 single-module Go repositories with green Linux baselines.
- Exclusions: fail-to-pass tests that do not compile at the parent; tests referencing identifiers introduced by the gold patch (unless signatures supplied, flagged); flaky tests (fail ≥1 of 3 clean reruns); under-specified or leaking task text (manual screen).
- Sample size (revised 2026-10-11): ≥200 confirmatory instances (stretch 300) after manual screening and the task-only screen; the 24-instance pilot (DOI 10.5281/zenodo.23307204) is disjoint and not reused. Power from pilot per-instance SDs: dense model ε=0.05, σ=0.083 (A1−A1b, Haiku) → >0.99 at n=200 (still >0.99 at σ=0.35); open-weights ε=0.075, σ between 0.26 and 0.42 (Sonnet P200−A1, all / screened instances) → 0.99 to 0.81 at n=200. Frontier subset n=100: 0.56 at σ=0.42, hence descriptive. Stopping rule: none; fixed n. If fewer than 200 survive after the tenth listed repository, run on the survivors and report the implied power.
- Margin (revised 2026-10-11 after the pilot, DOI 10.5281/zenodo.23307204): cell non-unanimity (0.25 on Haiku at k=10) is not usable as a margin basis. ε is set from the standard deviation of per-instance paired differences observed in the pilot: ε = 0.05 for the dense model (σ ≈ 0.11, n required ≈ 30 at 80% power) and ε = 0.075 for models run at k=3 (σ ≈ 0.25, n ≈ 69). Fixed here before the confirmatory run; no further change without a dated note.
- Screening (added 2026-10-11): the task-only arm is run first on the strongest evaluated model (k=3); any instance solved at least once is excluded from the confirmatory set and reported separately. In the pilot this removed 14 of 24 instances for Sonnet 5.5.
- Load range (revised 2026-10-11): padding levels 64k, 200k, 400k, 700k, 950k; a flat curve is an admissible outcome.

## 5. Variables
- Manipulated: context arm (A∅, A0, A1, A1b, A1F, A2, A4s, A4l, P64, P200, P400, P700, P950 × 3 padding types: same-repository code outside W∪B∪F with directory-proximity ceiling, cross-repository Go from a fixed listed repository, Go release-note prose).
- Measured: applied; Δ-pass; frame-pass; tokens in/out; latency; expressibility per arm; W_I flag; shared-helper flag; task-text source; cutoff flags.
- Indices: Δ-pass-and-frame-pass; tokens ratio A1/A2, A1/A4l.

## 6. Analysis plan
- Paired difference of proportions per contrast with a paired score (Tango/Newcombe) interval; Wilson intervals on all proportions; bootstrap over instances alongside.
- H2 (revised 2026-10-11): intersection–union; both lower bounds of the instance-level percentile bootstrap (2,000 resamples, seed 1, 95% two-sided) of the mean per-instance difference > −ε; level α=0.05 without further adjustment, tested first and alone. Tango score interval on majority outcomes reported alongside. H1: per model, one Holm family of nine superiority tests (3 levels × 3 padding types) at α=0.05; TOST at ±0.05 per level reported uncorrected as the pre-specified reading of a null superiority result. Instance set per (model, level) fixed before any call as the instances where that arm can be built.
- Per-instance ε-sufficiency only on cells with k = 3 samples; reported descriptively.
- Subgroup analyses (pre-specified, descriptive): by repository; by task-text source; by W_I; by shared-helper; by expressibility.
- Missing data: unapplied patches count as failures; API errors are retried three times then recorded as missing and excluded from that arm's pair with the instance flagged.
- Inference criteria: one-sided α = 0.05; H2 unadjusted (intersection–union), H1 after Holm within its nine-test family per model. No change to any item above after the first confirmatory model call; earlier changes are dated here.

## 7. Exploratory analyses
- Degradation curve shape per model; interaction of padding type with model; per-repository parametric-memory rate.

## 8. Deviations
Any deviation from this plan will be reported in a dedicated section of the Stage 2 paper with the reason and its date.

- 2026-10-12 (erratum to the pilot, DOI 10.5281/zenodo.23307204): instance cli__cli-0c2eea6338a2 was run with an empty task text (task_text_source "rewritten_spec" produced no text); it scored 0 on every arm and model and is invalid. Recomputed on 23 instances: Haiku 5.5 A1 Δ-pass 0.674 [0.491, 0.843] (was 0.646); A1−A1b +0.043 [+0.013, +0.078] (was +0.042 [+0.012, +0.075]); P200−A1 −0.029 [−0.129, +0.081] (was −0.03 [−0.15, +0.09]); Sonnet 5.5 solved 14/23 from task text (was 14/24). Conclusions unchanged. The instance is excluded from the ablation study. A mining check (non-empty task text) is added.
- 2026-10-12 (erratum to the pilot cost): Haiku 5.5 is billed at a higher rate for prompts above 100k tokens; 697 of 2,256 Haiku calls were above it. Pilot spend at list prices is about $73, not $61 (Haiku $16.44, not $4.71).
- 2026-10-12 (H5 exploratory run, harness fault): during the Haiku 5.5 ablation run (23 instances, k=20) the shared build helper was edited to read Go environment settings from the shell; the detached runner shells lacked them, so from about 09:00 every `go build` failed with "build cache is required" and 4,456 applied samples on 21 instances were recorded as build failures. Model outputs were unaffected and are stored with each record. The helper was fixed and every affected sample was re-verified locally: the stored response was re-applied at the base commit, accepted only if its patch hash equalled the original record's, and the build and test verdicts recomputed with the unchanged `verify` procedure; 4,409 samples were re-verified this way with no hash mismatch. The 44 samples whose stored response was truncated or had required a repair turn were discarded and re-sampled (about $0.30). The two instances that ran before the edit were untouched. The invalid originals are retained by the author. The faulty aggregate was seen before the repair; H5 is exploratory on these instances and its hypotheses were fixed above before any call.
- 2026-10-12 (analysis, after the exploratory H5 run; descriptive additions, no change to the decision rule): the report now prints the one-sided 95% lower bound that §6 specifies (the table previously showed only the two-sided interval's lower end, which is a one-sided 2.5% test), paired sign counts, the estimate without the most influential instance, counts of ceiling and floor instances, and a null reference for the necessity counts (all cells of an instance drawn from one pooled rate at k=20). The bootstrap generator uses seed 2 for paired differences and seed 1 for means (analysis/pilot.py), not seed 1 for both as §6 reads.
- 2026-10-12 (H5 exploratory reading, recorded before any further call): the W − A1 difference on Haiku 5.5 is carried by one instance (cli__cli-babd691446b9, W 0.35 vs A1 1.00); without it W is non-inferior to A1, so on 22 of 23 instances dependency interfaces add nothing measurable once the write-set bodies are present. The leave-one-out necessity counts (33 lower, 33 raise, of 135) match the null reference and carry no information at k=20; predictor precision and recall against that label are not interpretable. The task-text rule's whole-word package-name clause matched English words (`context`, `source`, `text`, `status`, `extension`) rather than code references.
- 2026-10-12 (amendment for the next H5 phase, fixed before any call): (i) the task-text predictor counts a dependency only when the task text contains a selector `alias.Name` resolving to it, or an exported identifier of that dependency inside a Markdown code span, or its import path; whole-word package names in prose no longer count. (ii) Instances enter the H5 contrast set only if W is inexpressible (a gold identifier is absent from W) and the W arm passes fewer than 80% of a k=5 screen on the dense model, so that the arms can separate; screened-out instances are reported as such. (iii) Per-dependency necessity is not estimated at k=20; where estimated, k ≥ 100 per cell and the null reference is reported alongside. (iv) Set-level precision and recall of the task-text predictor against the gold-referenced set are computed on every mineable instance without model calls, stratified by task-text source.
- 2026-10-13 (Phase 2 exploratory run, recorded after stages 2–5 and before any further call): the screen in amendment (ii) admitted floor instances (7 of 10 selected instances pass under 7% in every arm on Haiku 5.5), so only 3 instances could separate arms. Relative ε-sufficiency is vacuous when the best tested context is near zero; all further reports state a non-degeneracy condition (best arm ≥ 0.1) alongside ε and report absolute rates with relative ones. In the three cells where context changed the outcome, the passing patches introduced no identifier supplied only by dependency documentation; the effects are attributed to reader behaviour (load, framing, semantic reminders), not missing information. The leave-one-out stage (amendment iii) is restricted to the three responsive instances (A1 ≥ 0.1 on Haiku 5.5: caddy 6727b2f3a92b, caddy c8591a1e46e4, cli 2bcdfbb1ac02); completed samples on other instances are kept and reported as floor cells. Instance bd81afda9ab6 is absent from Phase 2 because its arms failed to build during a disk-full interruption. docker/cli has no root go.mod and was replaced by the next repositories on the §4 list (restic, golangci-lint).
- 2026-10-13 (amendment for Phase 3, fixed before any call): H6 (declaration-level context, descriptive with the same paired non-inferiority reading): arms Wd (the declarations of W reachable, through the type-checked reference graph, from identifiers used in the fail-to-pass tests and in task-text code spans or selectors, each file keeping its package clause and imports and marking omitted declarations), A1r (full W plus only the dependency declarations W references, rendered without bodies), Wdr (the slice plus the dependency declarations it references). Reading: Wd non-inferior to W and A1r non-inferior to A1 at ε=0.05, with token ratios. H7 (distraction versus load): Wpad = W preceded by inert same-module padding (pilot padding pool) matched to A1's prompt tokens; compared with A1 and W on the same instances. Screen: W and A1 at k=20 on Haiku 5.5; an instance enters when either rate lies in [0.1, 0.9]. Mining: M1 limits relaxed to at most 4 packages and 300 changed lines, recorded per instance as a mining profile and used as a stratum; previously examined commits rejected only by the old limits are re-examined. Models: Haiku 5.5 at k=50 (W, A1, A1t, Wd, A1r, Wdr, Wpad), Sonnet 5.5 at k=10 (W, A1, Wd, A1r, Wdr, Wpad); per-model spend caps enforced between instances. All contrasts are same-day paired within instance.
- 2026-10-18 (deviations recorded at write-up, after review of the Phase 3 report): (i) amendment (iv) of 2026-10-13, the set-level precision and recall of the task-text predictor on every mineable instance without model calls, was not performed. (iii) Phase 3 ran from 2026-10-13 to 2026-10-14; "same-day paired" above overstates it: the W and A1 cells began with the k=20 screen on 2026-10-13 and the remaining arms ran on 2026-10-13/14.
